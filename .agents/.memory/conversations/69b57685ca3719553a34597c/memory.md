## Active build plan — squirrel_os
Work through every step, and confirm each is satisfied before telling the user the agent is ready.

- [ ] 1. Create the core entities: AegisAnomaly, AegisPlaybook, AegisHealingEvent, SystemHealth, SystemHeartbeat, OrchestratorAgent, OrchestratorNode, OrchestratorTask, Pattern, Insight, NeuralNode, LearningMetric, PredictiveAlert, SelfImprovementProposal, RemediationSweep. Set up relationships: AegisHealingEvent references AegisAnomaly and AegisPlaybook; OrchestratorTask references OrchestratorAgent and OrchestratorNode; Pattern references AegisAnomaly and AegisPlaybook; PredictiveAlert references SystemHealth.
- [ ] 2. Deploy backend functions in dependency order: (a) healthCheck and systemMetrics as the data-collection foundation; (b) ameliaHeartbeat for the heartbeat cycle; (c) realSelfHealing and aegisPlaybookEngine as the core healing engine; (d) selfCorrectionAgent and monitoringAgent for continuous oversight; (e) agentOrchestrator for task dispatch; (f) pqcManager for cryptographic validation; (g) jasperRemediation as the top-level full-sweep orchestrator. Each function should be deployed and smoke-tested individually before the next is layered on.
- [ ] 3. Seed the AegisPlaybook entity with the initial set of repair manuals — one row per known anomaly type (e.g., prompt_drift, latency_spike, token_overrun, node_orphan, agent_overload, export_pipeline_stall, heartbeat_miss). Each playbook row contains: anomaly_type, detection_condition, isolation_steps, healing_steps, verification_steps, and a confidence_threshold.
- [ ] 4. Write operating rules to .agents/rules/squirrel_os_policy.md — these become the agent's behavioral guardrails injected into every conversation. Write the full rules file before testing any skill.
- [ ] 5. Create and test skills in order: heartbeat-check (foundation — validates the monitoring loop works), anomaly-response (core reactive loop), playbook-execution (healing engine), pattern-learning (self-improvement loop), full-system-sweep (Jasper's top-level sweep), agent-rebalance (resource optimization), diagnostic-isolate-heal (the master detect-isolate-heal protocol).
- [ ] 6. Authorize the Slack (bot) connector and create the #squirrel-os-alerts channel. Configure the two Slack automations (critical PredictiveAlert post + weekday health digest). Verify the bot can post to the channel before enabling the automations.
- [ ] 7. Register the cron automations: the 5-minute heartbeat cycle, the daily 03:00 full sweep, and the weekday 09:00 health digest. Validate each trigger fires correctly by running one cycle manually and confirming the downstream skill executes.
- [ ] 8. Run a full integration test: trigger a synthetic anomaly (e.g., inject a fake latency_spike AegisAnomaly), confirm the anomaly-response skill fires, a playbook executes, an AegisHealingEvent is created, a Pattern is updated, and a PredictiveAlert is generated if severity warrants it. Verify the Slack channel receives the alert.
- [ ] 9. Package the entire Squirrel OS layer as a reusable Base44 template: export the entity schema, backend functions, rules, skills, automations, and connector configuration as a deployable unit. Document the template deployment guide so any of the 150+ apps can adopt Squirrel OS in a single step.
- [ ] 10. Validate cross-app readiness: deploy the template into a second sandbox app, run the heartbeat cycle, and confirm all entities, functions, and automations activate correctly without modification.
